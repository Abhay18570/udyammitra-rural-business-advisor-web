## Provenance and status meanings

Every new imported record has `source_type=DATASET`, `source_dataset=updated_data.csv` (or the explicit input file's basename), and `verification_status=DATASET_ONLY`.

- **DATASET_ONLY:** imported discovery text; current official terms have not been verified.
- **OFFICIAL_SOURCE_LINKED:** an official source has been independently linked; this does not by itself verify every rule.
- **VERIFIED:** official information independently reviewed against current authoritative sources.
- **STALE:** reviewed information requires revalidation.

No workflow or automatic promotion to a reviewed status is implemented. A government URL inside source text does not change the status.

## Parsing and normalization

Python `csv.DictReader` uses strict parsing, `utf-8-sig`, and `newline=''`. The expected 11-column header is checked exactly. Quoted commas, multiline fields, Devanagari and ₹ survive ingestion. Malformed headers or CSV syntax abort before database changes. Wrong row widths and invalid catalog fields are reported as row failures while valid rows may proceed.

The unnamed artifact column is intentionally ignored and never persisted. Prose has BOM artifacts removed, outer whitespace trimmed and CR/CRLF normalized to LF; meaningful internal whitespace and original descriptions remain. Empty optional prose becomes null. Titles and list items have whitespace collapsed. Slugs are lowercased, trimmed and whitespace becomes hyphens; invalid remaining characters are rejected rather than silently removed.

Levels come exclusively from the CSV and normalize to CENTRAL/STATE. State and union territory names are matched case-insensitively with word boundaries in title, details, eligibility and application. A few explicit historic/spelling aliases normalize to canonical names, including Orissa/Odisha and Pondicherry/Puducherry. Exactly one distinct state must be present; absent or ambiguous evidence leaves state null. Central state is always null. Maharashtra always uses `Maharashtra`.

Categories/tags become JSON arrays, dropping empty and case-insensitive duplicate values while retaining the first spelling and order. Known category labels containing internal commas (Agriculture, Rural & Environment; Banking, Financial Services & Insurance; Science, IT & Communications) remain single values. No Python-list strings are stored.

## Identity, conflict policy and transactions

Exact duplicate source records, excluding the discarded artifact column, are skipped. Records sharing a normalized slug and identical normalized content are also skipped. If a slug has materially different normalized content within one file, **all versions of that slug are quarantined** and counted as conflicts; no arbitrary suffix or first-row winner is used. Conflict counts measure affected rows, not distinct slug groups.

Existing matching records are unchanged, preserving UUIDs and timestamps. Changed records are updated only when they belong to the same dataset and remain DATASET_ONLY. VERIFIED, OFFICIAL_SOURCE_LINKED, STALE and different-dataset records are protected: differing content is reported as a conflict. Identical protected records are simply unchanged. Re-import does not reactivate inactive records, downgrade verification, or delete records absent from a later file.

The repository uses the existing SQLAlchemy Session. Existing records are locked during comparison. Import writes commit in one transaction; fatal parsing/database errors roll back everything. A concurrent first-insert unique-key race fails safely and can be retried. Validation/conflict problems do not corrupt valid rows, but result in a nonzero CLI exit code. Database exceptions are reported by exception class only to avoid dumping credentials, SQL parameters or large descriptions.

## Commands

From the project root:

```sh
backend/.venv/bin/python backend/scripts/import_government_schemes.py --dry-run
backend/.venv/bin/python backend/scripts/import_government_schemes.py
```

From backend, with its environment active:

```sh
alembic upgrade head
python scripts/import_government_schemes.py --dry-run
python scripts/import_government_schemes.py --file data/updated_data.csv
```

The default CSV path is relative to the script's backend directory. Explicit relative `--file` paths resolve against the caller's working directory. The CLI then selects the backend working directory so the existing settings loader finds its usual `.env`; no parallel database configuration is introduced.

Dry run parses, validates, normalizes, deduplicates and compares against PostgreSQL. It does not write and rolls back its read transaction. It requires an accessible migrated database. Insert/update counts in dry-run output are projected counts. The parser can independently validate a CSV without database access.

## Limitations and exact next step

This is third-party discovery data, not verified official current eligibility. State extraction is a text hint and may miss or misattribute jurisdiction even with one match. CSV category capitalization/typos remain faithful to source. English FTS is not a multilingual stemming solution. There are no official source reviews, recommendation rules, API routes, source hashes/history or deletion synchronization in this phase. Operational errors abort with sanitized diagnostics; investigate locally without logging secrets.

**Recommended next task:** implement and test a read-only, paginated catalog list/detail API with level/state/category filters, basic text search, and explicit DATASET_ONLY provenance in its response contract. Review ambiguous jurisdiction data separately. Keep Module 12 unchanged and defer personalized matching and frontend redesign to separately authorized phases.
